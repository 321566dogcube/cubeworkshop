# 方块启动器 CubeLauncher

一个仿 **Plain Craft Launcher 2 (PCL2)** 界面风格的 Minecraft **Java 版**启动器，纯 C# / .NET Framework 4.8 编写，**无第三方依赖、无 SDK 依赖**，编译产物就是单个 `CubeLauncher.exe`。作者：**杯子狗**。

> 参考对象：`Plain Craft Launcher 2.exe` v2.13.1.1（C# 系启动器）。本项目只模仿它的**交互与视觉风格**，代码为全新实现。

## 快速开始

1. 双击 `dist\CubeLauncher.exe`。
2. 首次启动读取配置里的游戏目录（默认 `%APPDATA%\.minecraft`，可在设置里改）。
   本机打包时已把它指向 `build\_demo` 示例目录——里面已装好可运行的 **1.8.9**，打开就能直接点「启动游戏」。
3. 若本地没有版本：进「下载」页 → 选「正式版」→ 点「安装」，装完自动跳到启动页。
4. 选好版本 → 点右下角「启动游戏」。

配置文件：`%APPDATA%\CubeLauncher\settings.json`
运行日志：`%APPDATA%\CubeLauncher\logs\launcher.log`

## 功能

### 启动闪屏（新增）
仿 PCL2：双击图标后不是直接甩出主界面，而是先在屏幕正中弹一个只含 logo 的小方窗，主界面准备好再淡出。

- 232×232 圆角窗口（`Region` 裁圆角，四角是桌面本身）、无边框、不进任务栏、置顶
- 中央蓝色渐变圆角方块 + 白色 `C`，方块带一圈极淡光晕，并且**呼吸缩放**（96→99.6 px，约 3.6 秒一个来回，正弦）
- 下面一行名称与版本「方块启动器 1.0.0」，再一行当前阶段（`正在读取配置` → `正在准备界面`）
- 底部一条 2px 细轨道，一段高光从左扫到右（不确定进度），不显示假百分比
- 淡入 200ms / 淡出 220ms；**最低停留 1.1 秒**——否则版本缓存命中时初始化只要 300ms，闪屏会一闪而过，反而像闪屏
- 主题跟随配置：`App.Init()` 读完 `settings.json` 后按 `themeMode` 切底（暗色 `#1A1C22` / 亮色 `#FAFBFD`）
- 闪屏构造或显示失败会被静默跳过（`try/catch`），绝不会因为它把启动链拖死
- 实测：冷启动约 1.4–2.1 秒出现闪屏（这段是本机 .NET 冷启动 + JIT，不是闪屏本身慢），闪屏到主界面总计约 2.5–3 秒

### 启动护栏（新增：预检 / 备份 / 计时 / 崩溃归类）
配置独立存在 `%APPDATA%\CubeLauncher\guard.json`，不往 `settings.json` 里加字段（那个文件是手写拼的 JSON，少改少错）：

```json
{ "preflight": true, "autoBackup": true, "backupKeep": 3, "timing": true }
```

- **启动前完整性预检**：复用启动计划（`BuildPlan`）的真实解析结果，把缺的版本 jar、natives、类库、资源列出来，日志写「缺少 N 个文件（首个：xxx）」并逐条列出完整路径。**只报告不拦启动**——缺文件也允许试着进，真起不来会由下面的归类说明原因
- **启动前备份存档**：把 `<游戏目录>\saves` 下每个世界打成 `backups\saves-<版本>-<时间戳>.zip`，日志写「N 个世界，X MB」。两个关键细节：
  - **30 分钟内刚备过就跳过**，不然一天点十次启动就压十份几十 MB 的存档
  - 备份时跳过 `session.lock`（游戏正占用它，硬读会失败），其余文件按共享读方式流式写入，不整块进内存
  - 保留份数按 `backupKeep` 删旧的（默认 3 份，范围 1–20）
- **启动耗时统计**：日志写「启动耗时：预检 Xms · 备份 Yms · 总计 Zms（到进程起来为止，不含进窗口）」，同时追加一行到 `%APPDATA%\CubeLauncher\launch-times.jsonl`（版本/预检/备份/总计/是否成功/时间），后面做启动速度对比直接读这个文件
- **崩溃归类**：进程非 0 退出时，按「退出码 + 日志尾部」翻成人话，覆盖内存不足、Java 版本不匹配、类库缺失、类库冲突、启动类找不到、账户校验失败、资源下载失败、连不上服务器、模组初始化崩溃、显卡层崩溃（0xC0000005 / 0xC0000409）等，最后兜底给出「看日志最后 30 行找 Exception」
- 两个必须踩过的坑（都已修）：
  1. **Java 的本地化报错是 GBK**，用 UTF8 解会变乱码（`����: �Ҳ���...`），导致英文关键词归类全部失效 → stderr 改用 GBK 解码
  2. **日志是 800ms 批量落盘的**，进程刚退出那一刻最近几行还在内存里，读日志文件会「看不见」刚才的报错 → 归类改为优先读内存环形缓冲，拿不到再退回读文件

### 启动页
- 扫描 `<游戏目录>\versions\*`，自动识别 `version.json` / `<id>.json`，按发布时间排序
- **自动合并 `inheritsFrom`**：Forge / Fabric / OptiFine / 整合包的版本可以正常识别与启动（类库、参数、mainClass、assetIndex 逐层合并去重）
- 版本卡片显示类型（正式版 / 快照 / 远古）、发布日期、所需 Java、就绪状态
- 底部信息栏：离线账户、内存分配、所需 Java、游戏状态
- 双击版本卡片可直接启动；「+ 添加新版本」卡片直达下载页
- 可折叠的「运行日志」面板，实时显示启动命令行与游戏 stdout/stderr（自绘日志视图：等宽字体、错误红色 / 警告橙色、滚轮回看）

### 下载页
- 从 BMCLAPI 镜像（默认）或官方源读取 `version_manifest_v2.json`，共 900+ 个版本
- 筛选：全部 / 正式版 / 快照 / 远古 / 已安装，支持按版本 ID 搜索
- 一键安装：版本 JSON、客户端 jar、全部类库（含 natives 分类包）、资源索引、资源对象
- 16 线程并发下载，逐文件断点跳过（已存在且大小一致即跳过）
- 单个文件连接停滞超过 18 秒会被看门狗线程主动中断重试；主源（BMCLAPI）失败自动换用备用源（官方源）
- 安装进度直接显示在对应版本行上（百分比 + 阶段 + 文件计数）
- **可以中途取消安装**：点某行的「安装」后，顶部筛选条右侧出现「✕ 取消」按钮，点了就把下载服务的取消标志置位，正在进行的线程会自然停下，界面立刻收回「正在取消…」；取消后**不弹「安装失败」**，只把这条半成品清理掉——**只删「该版本目录里一个 jar 都没有」的版本目录**，已经下载好的文件不动（重装会命中断点跳过）

### 设置页
- **微软账户（正版登录）**：设备码授权流程，登录后 `auth_access_token` / `auth_uuid` 用正版令牌，`userType=msa`
- 游戏目录（浏览 / 直接打开）
- 玩家名称（离线登录；默认留空，输入框里有浅色提示，未填写时点「启动游戏」会提示先去设置页填昵称；UUID 由 `MD5("OfflinePlayer:<name>")` 按 v3 规则生成）
- Java 运行时：自动探测 + 手动指定；探测来源包括
  `<游戏目录>\runtime\*`、`Program Files\Java|Adoptium|Zulu|Microsoft|Corretto|Temurin|BellSoft|GraalVM|JetBrains`、`JavaSoft` 注册表、`JAVA_HOME`
- 内存分配滑条（默认系统内存一半，上限为物理内存 − 512MB）
- 窗口尺寸（留空 = 用版本默认；填写则自动追加 `--width/--height` 并开启 `has_custom_resolution`）
- 主题配色（6 色，立即生效并写入配置）
- 下载源切换（BMCLAPI / 官方）
- 启动后自动最小化启动器
- 额外 JVM 参数 / 额外游戏参数（支持 `${...}` 变量替换）
- 快捷操作：打开游戏目录 / 日志 / 配置目录
- **外观**分区（新增）：**背景图片**（选图 / 恢复纯色）与**背景暗化**滑条，详见下一节

### 自定义背景（新增）
- 「选择图片」支持 JPG / PNG / BMP / GIF / WEBP（走 `Image.FromFile`，GIF 取首帧），选完立即生效并写入配置 `backdropPath`
- 铺法固定为 **cover**：等比放大到刚好铺满内容区，居中裁切多余部分，不会留黑边也不会被拉扁；原图长边超过 2560 像素时先缩一道再缓存，省内存
- 读图时会复制一份，**不锁住用户的原文件**，之后随便挪动或删除原图都不影响已经缓存的背景
- **暗化**（0–90%，默认 55%）在贴图时叠一层半透明黑，所以拖滑条是即时生效的，不需要重建缓存；「恢复纯色」把配置清空并回到纯色深底
- 背景同时铺在启动页、下载页、内容页（含已装 / 详情视图）、设置页、关于页；标签栏、标题栏、列表控件保持纯色面板，保证卡片和文字清楚
- 性能上做了三件事：① 按窗口尺寸缓存成一张 24bpp 位图，只有窗口尺寸变化才重建；② 贴图用 `CompositingMode.SourceCopy` 跳过逐像素 alpha 混合；③ 只按每个控件自己的覆盖区域贴对应子图（`DrawImage` 带源矩形），大图不会被整张重画
- 拖动窗口改尺寸时先去抖 140ms，期间把旧缓存按比例拉伸顶上，避免每帧都重新缩放一次大图

### 工具页（新增，左侧导航第 6 项）
- **主题**：夜色 / 明亮两套配色一键切换，切完立即重绘全窗并写进配置 `themeMode`；背景图、卡片、文字色都跟着换，亮色下不会残留暗色块
- **主色**：除 6 个预设外新增「自定义色」，打开系统取色器选任意颜色，存成 `accent=custom:#RRGGBB`；非法色值自动回落到默认蓝，不会把界面调成看不见的颜色
- **界面缩放**：100% / 110% / 125%，按倍率放大全部字号并同步放大窗口，字体缓存自动重建（不是简单拉伸位图）
- **关闭到托盘**：开启后点右上角 ✕ 只把窗口收进托盘（进程不退出），托盘图标双击回来、右键菜单可「显示启动器 / 退出」；首次收起会弹一次气泡提示
- **启动提示音**：启动成功后播一声系统提示音，可关
- **记住窗口**：位置与尺寸写入配置（`winX/winY/winW/winH`），下次启动按原位置恢复；还会校验记录的位置是否落在当前任一块屏幕内，避免换显示器后窗口跑到画面外
- **导出配置**：把 `settings.json` + 环境信息打成 zip，导出时**登录令牌被清空**（`msAccessToken` / `msRefreshToken`），可以直接发给别人排查
- **导入配置**：把 zip 里的配置写回本地，写入前把现有配置备份成 `settings.json.bak`；导入时会**保留本机已有的正版登录令牌**，不会因为换个配置就把账户弄丢
- **打包日志**：`logs` 目录 + 脱敏配置 + 环境信息 + 最近日志缓冲一起压成 zip，方便发出来定位问题
- **快捷键**：`Ctrl+1…6` 切页（启动 / 下载 / 内容 / 设置 / 关于 / 工具）、`F5` 重新扫描版本、`Ctrl+L` 开关运行日志、`Esc` 取消进行中的启动

### 版本扫描缓存（新增）
- 启动页每次刷新都会重扫 `versions` 目录。现在按「目录指纹」（versions 目录自身 + 各版本子目录的修改时间之和）判断，结构没变就复用上次结果，5 分钟内不重复读盘；新增或删除版本会立刻失效重扫
- 命中缓存时日志里会写一行「版本列表命中缓存（N 个版本）」，方便确认

### 联机大厅（新增，左侧导航第 7 项）
- **本机开房**：点「开一个房间」，用官方 1.8.9 服务端在本机起一个**离线模式**房间（首次使用自动下载 `server.jar`，约 8 MB，存到 `<游戏目录>\servers\1.8.9\`）
- 为什么不用游戏里的「对局域网开放」：那种房间强制在线校验，离线账户会被服务端直接拒（`Invalid session`）；自建服务端把 `online-mode=false` 才是能直接进的
- 房间目录 `servers\room_<端口>`，写 `eula.txt` + `server.properties`（`max-players=8`、`spawn-protection=0`、`allow-flight=true`、`difficulty=1`、`view-distance=8`）
- **自动发现**：房主端每 1.5 秒往 `224.0.2.60:4445` 播一条 `[MOTD]房间名[/MOTD][AD]端口[/AD]`；同网其他启动器打开联机页就能看到，不需要端口映射、不用记 IP
- **房间列表**：显示房间名、`IP : 端口`、「N 秒前广播」，自己的房间标「（我的房间）」并高亮；广播断了会按年龄自然从列表消失
- **一键加入**：点「加入」用启动页选中的版本直连（带 `--server` / `--port` 启动参数），不用再进多人游戏界面手动输入
- **在线人数**：解析服务端输出里的 `xxx joined the game` / `xxx left the game` 实时刷新面板上的「N 人在线」
- **关闭房间**：发 `stop` 让服务端正常保存退出，8 秒不退才强杀；关完广播停止、房间从列表消失、端口立即释放
- **端口占用检查**：开房前先试 bind 一次，被别的程序占着会直接提示「端口 xxx 已经被别的程序占用了，换一个」，不会留下半开状态（实测旧服务端占着 25565 时正是这条提示拦下的）
- **手动直连**：底部填 `IP` + `端口` 直接进，适合跨网段或朋友不在同一广播域的时候

### 音乐播放器（新增，左侧导航第 8 项）
- **本地曲库**：指定一个音乐文件夹，扫描 mp3 / wav 列成列表，播放引擎走系统 MCI（`mciSendString`），不引第三方解码库；播放 / 暂停 / 上一首 / 下一首 / 拖动进度 / 音量都在同一页
- **自动续播**：一首播完自动切下一首，进度条按真实位置推进（实测 3 秒短曲播完即切到下一首，继续从 `0:02/0:15` 往前走）
- **置顶迷你播放器**：336×84 无边框小窗、`TopMost`、圆角 `Region`、可拖动并记住位置；双击回到主界面音乐页，底部一条细进度线；启动游戏成功后按 `musicMiniOnLaunch` 自动浮出，游戏中也能继续听
- **网络曲库（Jamendo）**：走官方 `v3.0/tracks` 接口搜索 CC 授权音乐，双击结果下载 mp3 到临时目录后交 MCI 播放；**搜索与播放不需要登录任何账号**，只需在 devportal.jamendo.com 免费注册一个应用（不是个人账号）并把 `client_id` / `client_secret` 填进窗口；「登录」按钮走 Jamendo 官方 OAuth 授权码流（本机 `HttpListener` 监听 `http://127.0.0.1:35719/callback`），是可选项
- **六个平台卡片只做展示与跳转**：网易云 / QQ 音乐 / 酷狗 / 酷我 / YouTube Music 标注「无公开接口 · 仅跳官网」，Spotify 标注「可授权 · 需自建应用」，点卡片只打开官网，**不写假的「已绑定」**。本软件不通过任何非官方逆向接口抓这些平台的曲库
- 免密钥曲源实测结论（决定「零配置听歌」做不到）：`archive.org` 请求超时（国内不可达）、`api.deezer.com` 域名解析失败、iTunes Search 可用但只返回 `.m4a` 试听流，而 MCI 打开返回码 277、本机 `WMPlayer.OCX` 未注册，无法解码。因此免密钥 + 国内可达 + 能解码成 mp3 三个条件无法同时满足，唯一验证过能真实出声的网络路径是 Jamendo 的 mp3

### 内容页（模组 / 光影）
- 资源数据来自 **Modrinth**（`api.modrinth.com`），无需登录、无需 API Key
- 顶部切换「模组 / 光影」；模组可再选加载器（自动 / Fabric / Forge / NeoForge / Quilt）
- 自动读取启动页当前版本：把版本 ID 里的游戏版本号（`1.20.1-forge-47.2.0` → `1.20.1`）和加载器（forge / fabric / neoforge / quilt）作为筛选条件
- 每个结果行显示项目**真实头像**、作者、累计下载、分类，点「安装」自动挑该版本下主文件下载
- 模组装到 `<游戏目录>\mods`，光影装到 `<游戏目录>\shaderpacks`，文件名保持 Modrinth 原名；下载走 `.tmp` + 改名的原子落盘，进度百分比显示在按钮上
- 当前版本是原版（没有加载器）时，点安装会提示先选一个加载器，避免把 jar 装进一个永远不会读它的版本里
- **装模组时自动带上必需前置**：Modrinth 把前置写在版本的 `dependencies` 里，安装前先按同一游戏版本 / 加载器把 `required` 的项目逐个装好（已在 mods 目录里的会跳过），日志里会写「前置已安装」
- **点项目图标 / 标题进入详情页**：项目简介、作者、累计下载、关注数、更新时间、支持的加载器、分类标签，右上角「项目主页」「打开模组目录」
- 详情页列出**该项目的全部版本**（最多最近 300 个）：版本号、兼容的游戏版本、加载器、发布日期、文件名与大小；每个版本可单独安装，已装的显示「已安装」，下载中按钮显示百分比并在行底走一条细进度条
- 版本区可按「适配当前版」筛选，命中的行带绿色「适配当前」徽章；版本很多时右侧有细滚动条
- **点版本行（不是按钮）会弹出该版本的更新日志**：把 Modrinth 的 Markdown 压成纯文本、按宽度自动换行、可滚轮翻阅，底部显示文件名与大小，并可直接「安装此版本」；点 × 或面板外任意处关闭
- 「打开 mods」「打开 shaderpacks」直达文件夹
- 项目头像直接取 Modrinth 的 `icon_url`：后台线程逐个下载（带 UA、直连、15 秒超时），统一居中裁成 128×128 存成 PNG 放在 `%APPDATA%\CubeLauncher\icons\<项目ID>.png`，下次启动直接读盘；WebP 由系统自带的 WIC（WPF `BitmapDecoder`）解码，不引第三方库
- 头像还没下好或下载失败时，先显示项目首字母的色块占位，下好后自动替换，不会卡界面

### 已装管理（内容页第三个标签「已装」）
- 顶部三个标签：**模组 / 光影 / 已装**；点「已装」进入已装文件视图（也可以 `CubeLauncher.exe --installed` 直达）
- 逐条列出目标目录里的 `.jar` / `.zip` / `.jar.disabled`：真实头像、文件名、大小、修改时间、版本号、来源（项目名或「外部文件」），行间有细滚动条
- 每行三个操作：**删除**（删文件并从 `installed.json` 索引里去掉记录）、**禁用 / 启用**（用 `.disabled` 后缀改名，游戏不读它但文件还在，行会变灰并加删除线）、**升级**（有新版时出现，直接下载新文件、删掉旧文件并更新索引）
- **更新检查**：进「已装」后后台逐条向 Modrinth 查该项目在当前游戏版本 + 加载器下的最新版本，与索引里记录的 `versionId` 不同就标出「升级」；当前没选加载器时沿用这条记录自己的加载器，所以不会把 Fabric 版误升成 NeoForge 版
- **mods 目录策略可切换**：右上角「mods 共用 / mods 隔离」芯片。共用 = `<游戏目录>\mods`（所有版本共用一套模组）；隔离 = `<游戏目录>\versions\<当前版本>\mods`（每个版本各一套）。切换立即写入配置 `"modsIsolation"`，安装、已装列表、打开目录都跟着走
- **导入整合包**：点「导入整合包」选 `.mrpack`，读取包里的 `modrinth.index.json`，按清单逐个下载（`env.client = unsupported` 的服务端文件跳过，已存在且大小一致的跳过），再解压 `overrides/` 与 `client-overrides/` 到游戏目录，进度实时显示在这一行副标题上
- **导入可以中途取消**：导入过程中按钮变「✕ 取消导入」，点了会在下载循环与解压循环的下一次检查点抛出 `PackCancelled` 立即中止（不是等这一轮跑完），状态栏提示「已取消导入整合包（已下载的文件保留，重新导入会跳过）」，按钮复位

### 启动流程（核心）
- 类库规则判定：`os.name` / `os.arch` / `os.version` 正则 / `features`（含 `has_custom_resolution`）
- natives 分类包自动解压到 `versions\<id>\natives`
- 类路径拼接（类库 + 客户端 jar），并识别 `jar` 字段指向的父版本客户端
- 同时支持现代 `arguments.jvm` / `arguments.game`（含逐项规则）与旧版 `minecraftArguments` 两种参数格式
- 参数变量替换：`${auth_player_name}` `${auth_uuid}` `${auth_access_token}` `${classpath}` `${natives_directory}` `${assets_root}` `${assets_index_name}` `${version_type}` 等 18 个
- 自动避免重复的 `-cp` / `-Djava.library.path`
- 自动按版本要求匹配 Java（8 / 17 / 21 / 25），版本 JSON 无 `javaVersion` 时按发布时间推断
- 缺失文件会在启动前汇总告警到日志，不会静默失败

### 启动动画（Minecraft 原版 / LabyMod 风格开机画面）
- 点「启动游戏」后立刻在**整个客户区**（含左侧导航与标题栏）盖一层开机画面：**整屏红底**（`#D8261A`，上下压两道暗角渐变）+ 顶部居中一行小品牌（白色圆角徽标 + 字距拉开的 `CUBELAUNCHER`）+ 正中**巨大白色字标** + 下方字距更开的一行 `BLOCK LAUNCHER · MINECRAFT JAVA` + 版本行 `1.21.11 · 正式版`
- 底部是 Minecraft 开机那条**细进度条**：白色 1.6px 描边框 + 白色填充 + 头部一块**比条本身更高的白色端帽**（端帽跟着填充走，到 100% 正好贴右框内侧）；进度未知时画一小段白块来回扫
- 字标字号不是写死的：先按 20pt 探针用 `GenericTypographic` 紧凑量出整词宽度，再按 `目标宽 = min(0.74 屏宽, 860)` 反推字号，所以换窗口尺寸、换 DPI 都不会溢出屏幕；副标题同样按目标宽度收，字距是字号的 0.22 倍（模仿原版 `STUDIOS` 那行）
- 纵向排布用**实测行高**（`MeasureString` 的整行高度）而不是拿字号猜，字标 / 副标题 / 版本行三行之间不会互相压
- 进度和阶段文案来自**真实启动阶段**：`GameLauncher` 在「读取版本配置 → 匹配 Java 运行时 → 校验类库 i/N → 拼接类路径 → 准备玩家身份与资源索引 → 组装启动参数 → 启动 Java 进程 → 等待游戏窗口出现」这 8 个点位回调百分比；条上方左侧是阶段文案（换阶段时淡入）、右侧是百分比数字，百分比用时间常数平滑逼近，不跳变
- 入场先淡入 0.42 秒（红底不会「啪」地出现）；成功后停 1.05 秒、失败停 2.4 秒、取消停 1.0 秒再淡出
- 失败时整块转深栗色（`#4A0E0A`），阶段行变「启动失败」，进度条上方下面折行显示原因（最多 3 行，超出加省略号），底部提示「按 Esc 或点击任意处返回」，Esc 或点一下就能收起
- 淡出前会先用 `PrintWindow` 抓一张启动前的窗体快照垫在最底层，整层带 alpha 一起渐隐，所以结束是「化回页面」，不会闪一下黑底
- **可以中途取消**：进度条下方一行小字「✕ 取消启动」（鼠标移上去变白并在字下加一条细线，光标变手型），按 Esc 同样可以；取消后底图转暗红、条冻在当前位置、提示变「已取消本次启动，正在返回启动页」，1 秒后淡出回页面
- 取消是**真的中止**：构建阶段直接中止（每个阶段回调点都会检查取消标志），如果 Java 进程已经拉起来了就把它 `Kill` 掉，已解压的 natives 等中间产物保留不影响下次启动；随后启动页按钮复位成「启动游戏」、游戏状态回「未启动」，日志留一行「用户取消了本次启动」
- 每轮启动都有一个自增的代次号，取消时 +1，这样上一轮迟到的进度回调会被全部丢掉，不会把取消后的界面又改回「正在启动」
- 性能：红底 + 字标 + 副标题整张**只渲染一次**缓存成 24bpp 位图（尺寸或状态色变化才重建），每帧只贴一次图 + 画笔进度条 + 画三行小字，1080×700 实测 **14.6 ms/帧**
- 「启动后自动最小化」只在成功后生效（失败会留在原地让你看原因）

## 微软正版登录

整个流程都在启动器内完成，只需要你在浏览器里输入一次代码：

1. 设置页「账户」分区 → 点「微软登录」（或命令行 `CubeLauncher.exe --login`）
2. 弹窗显示 8 位设备码，点「打开登录页」跳到 <https://www.microsoft.com/link>，输入代码并授权
3. 启动器自动轮询，接着依次完成：微软令牌 → Xbox Live 认证 → XSTS 授权（RETAIL）→ Minecraft 服务登录 → 读取游戏档案
4. 成功后写入配置：`msAccessToken` / `msUuid` / `msName` / `msRefreshToken`，启动页底栏立刻变成「微软账户 · 正版登录」

要点：

- 使用官方公开的 OAuth 客户端 ID `00000000402b5328`（与 PCL2 等第三方启动器同一套设备码流程），全程不接触密码
- 游戏参数改为正版令牌 + 正版 UUID + `--userType msa`；未登录时仍走离线登录（`--userType legacy`，accessToken 为 `0`）
- 设备码有效期 15 分钟，超时或网络失败可点「重新获取」；点「退出登录」清空令牌回到离线模式
- 常见失败原因已翻成人话：账户没有 Xbox 档案、地区不支持、未成年需加入家庭组、未购买 Minecraft Java 版

### 登录链路的几处修正（本轮）

原来的「正版登录不了」主要卡在 Xbox Live 那一步，修了三件事：

1. **RpsTicket 必须带 `d=` 前缀**。设备码流程拿到的是 MSA（Live SDK）令牌，按 Xbox 认证规范 `RpsTicket` 要写成 `d=<token>`，之前裸传令牌会被 `user.auth.xboxlive.com` 直接 401。现在 `AuthService.RpsTicket()` 负责加前缀（空值安全、已带前缀不重复加），并做成「先 `d=`、失败再裸令牌重试一次」的双尝试，两步都失败才报错。
2. **refresh_token 取错了字段**。以前把 `access_token` 当 `refresh_token` 存进配置，续期必然 `invalid_grant`；现在解析响应里真正的 `refresh_token`，并记住令牌到期时间（`msExpiresAt`）。启动前如果令牌过期（留 1 分钟余量）且本地有刷新令牌，会在后台静默续期一次再启动；续期失败只记日志、不拦启动。
3. **错误信息能看懂**。每一步（XBL / XSTS / Minecraft / 档案）失败都会带上接口原文压成一行（≤220 字），并区分「未购买 Java 版」「令牌失效请重新登录」等情形；日志里也会留下「Xbox Live 认证通过」「Minecraft 服务令牌已获取」这类阶段标记，方便对日志判断卡在哪一步。

> 注：设备码申请（`login.live.com/oauth20_connect.srf`）在本机实测可拿到可用 `user_code`；XBL / XSTS / Minecraft 三步必须由真实账户在浏览器里授权后才能走通，这部分请以你实际登录一次的结果为准。

## 安装包（SETUP.EXE）

`dist\CubeLauncher-Setup.exe` 是独立的安装向导，约 225 KB，把启动器本体作为资源内嵌，双击即可安装：

- 深色自绘无边框窗口，四步向导：欢迎 → 选择目录 → 安装进度 → 完成
- 默认装到 `%LOCALAPPDATA%\Programs\CubeLauncher`（当前用户级，不需要管理员权限）
- 可选创建桌面快捷方式、开始菜单项（含「卸载 方块启动器」）
- 写 HKCU 卸载信息（DisplayName / DisplayVersion / Publisher / DisplayIcon / InstallLocation / UninstallString / QuietUninstallString / EstimatedSize / NoModify / NoRepair），在「应用和功能」里可见可卸
- `uninstall.exe --uninstall` 自助卸载：删快捷方式与注册表、延迟删除自身与目录，保留 `%APPDATA%\CubeLauncher` 下的配置与日志
- 静默安装：`CubeLauncher-Setup.exe --dir=D:\Tools\CubeLauncher --silent`
- 界面向导和静默模式走同一个 `InstallCore`（建目录 6% → 写文件 28% → 卸载器 46% → 快捷方式 60% → 注册表 78% → 收尾 92% → 100%），所以两种路径装出来的结果完全一致

## 已知边界（当前版本未实现）

- 只做**离线登录 + 微软正版登录**；Authlib-Injector 外置登录未接入
- 没有内置 Java 自动下载（依赖本机已有 Java 或 `.minecraft\runtime`）
- 内容页只接 Modrinth（未接 CurseForge）；整合包只支持 `.mrpack`（CurseForge 的 `.zip` 整合包不支持）
- 只有本启动器装的文件能查到来源与更新；从别处拖进 `mods` 的 jar 在已装视图里标「外部文件」，不能查更新、不能一键升级（可以删除、禁用）
- 前置依赖只装 `required` 里、且能在当前游戏版本 + 加载器下找到文件的那些；`optional` / 版本号被钉死的前置不自动处理
- 没有自动更新、皮肤
- 联机大厅以「本机当房主 + 同网广播」为主：跨公网需要自己做端口映射或内网穿透；房间固定是 1.8.9 离线模式（其他版本还没有对应服务端管理）；服务端首次下载需要能访问 Mojang 官方下载地址
- 头像解码依赖系统的 WebP 支持（Windows 10 1809+ / Windows 11 自带 WIC 解码器）；若系统缺这个解码器，头像会退回字母色块，功能不受影响
- 界面按 100% DPI 布局设计；高 DPI 下由系统整体缩放（略软，但不会错位）
- 自定义背景统一按不透明位图缓存（不吃 PNG 的透明通道）；GIF 只取第一帧；超大图（长边 > 2560）首次建立缓存约 90ms，之后每帧只是一次贴图
- 背景图被删掉或改名后，启动会自动回落到纯色底（配置里仍保留路径，换回文件即恢复），不会因此报错
- 正版登录的设备码申请、令牌续期逻辑本机已验证；XBL / XSTS / Minecraft 三步需要真实账户在浏览器授权后才能走通，最终结果以你实际登录一次为准（失败时日志里会停在具体哪一步）

这些都可以在现有结构上继续加：`DownloadService` 已有镜像重写与并发下载底座，`GameLauncher.BuildPlan` 已把认证字段做成变量替换，接正版登录只需替换 `${auth_access_token}` 等变量。
